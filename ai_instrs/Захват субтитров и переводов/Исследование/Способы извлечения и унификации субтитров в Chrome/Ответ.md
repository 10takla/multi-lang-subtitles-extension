# Краткий вывод

**Универсальный подход есть частично.**

Можно унифицировать **модель субтитров**: список `cue` с `start`, `end`, `text`.

Но нельзя единообразно получать субтитры со всех сайтов одним API. Практическая архитектура:

`TextTrack → прямой subtitle-файл → HLS/DASH → player API → platform adapter → DOM fallback`

# 1. Стандарты

## WebVTT

Основной веб-формат субтитров.

```html
<video>
  <track kind="subtitles" src="en.vtt" srclang="en">
</video>
```

Получение:

```js
const video = document.querySelector('video');

for (const track of video.textTracks) {
  for (const cue of track.cues ?? []) {
    console.log(cue.startTime, cue.endTime, cue.text);
  }
}
```

Основной объект:

```text
TextTrack
 └─ TextTrackCue[]
      ├─ startTime
      ├─ endTime
      └─ text / payload
```

`track.cues` — известные браузеру cues.

`track.activeCues` — только текущие.

Если:

```js
track.mode === 'disabled'
```

браузер может вообще не загрузить cues. Для чтения можно временно поставить:

```js
track.mode = 'hidden';
```

---

## TTML / IMSC

XML-форматы timed text, распространены в профессиональном streaming и OTT.

Пример:

```xml
<p begin="00:01:03.200" end="00:01:06.100">
  Hello world
</p>
```

Chrome не предоставляет универсального `TextTrack` API для произвольного TTML-файла.

Нужно:

`fetch → XML parser → собственная cue-модель`

IMSC — профиль TTML для субтитров.

---

## SRT

Популярный, но не браузерный стандарт.

Chrome не поддерживает SRT через `<track>` напрямую.

Нужен простой собственный parser.

---

## CEA-608 / CEA-708

Broadcast closed captions.

Могут быть встроены непосредственно в медиапоток, а не существовать отдельным `.vtt`.

Иногда player/browser превращает их в `TextTrack`, но это не гарантировано.

Для гарантированного извлечения часто нужен разбор media segments.

# 2. Общая модель данных

Лучше не хранить browser `TextTrack` напрямую, а нормализовать всё в собственную модель:

```ts
interface SubtitleCue {
  id?: string;
  startMs: number;
  endMs: number | null;
  text: string;

  speaker?: string;
  final?: boolean;
}

interface SubtitleTrack {
  id: string;

  language?: string;
  label?: string;

  kind: 'subtitles' | 'captions' | 'descriptions' | 'unknown';

  format:
    | 'webvtt'
    | 'ttml'
    | 'imsc'
    | 'srt'
    | 'cea608'
    | 'cea708'
    | 'json'
    | 'unknown';

  source:
    | 'texttrack'
    | 'file'
    | 'hls'
    | 'dash'
    | 'player-api'
    | 'network'
    | 'dom';

  live: boolean;

  completeness:
    | 'full'
    | 'loaded-window'
    | 'active-only'
    | 'unknown';

  cues: SubtitleCue[];
}
```

Минимальный общий знаменатель:

```text
start + end + text
```

# 3. HLS и DASH

## HLS

Типичная схема:

```text
master.m3u8
 → subtitle playlist
 → en.m3u8
 → 001.vtt
 → 002.vtt
 → ...
```

Для VOD можно скачать весь playlist и все subtitle segments → получить полный transcript.

Для live обычно доступно только текущее sliding window. Старые сегменты исчезают, поэтому их надо сохранять по мере получения.

---

## DASH

Пример:

```text
MPD
 └─ AdaptationSet type=text
      └─ Representation
           └─ subtitle segments
```

Форматы часто:

- WebVTT
- TTML
- IMSC

VOD обычно можно собрать полностью.

Live — только доступное временное окно.

---

# 4. Реальные платформы

## YouTube

Официальный Captions API существует, но скачивание captions требует OAuth и прав на редактирование видео.

Для произвольного просматриваемого видео это не универсальное решение.

Web player использует собственный caption pipeline и внутренние endpoints.

Также текущие captions отображаются в DOM.

Итого:

```text
YouTubeAdapter:
  internal player data
  / network captions
  / DOM fallback
```

Отдельный адаптер нужен.

---

## Netflix

Использует профессиональные timed-text форматы, включая TTML/IMSC.

Но браузерный subtitle pipeline — внутренний и не является стабильным публичным API.

Generic `video.textTracks` недостаточен.

Нужен `NetflixAdapter`.

DRM дополнительно ограничивает доступ к media pipeline.

---

## Vimeo

Заметно удобнее.

Player SDK позволяет:

```js
player.getTextTracks()
player.enableTextTrack()
player.on('cuechange', ...)
```

Через API доступны subtitle resources в VTT/TTML/SRT.

Поэтому Vimeo можно интегрировать через документированный API.

---

## Coursera

Субтитры могут приходить как VTT/SRT или через lesson/player metadata.

Но стабильного универсального viewer API нет.

Практически нужен `CourseraAdapter`.

---

## Произвольные `<video>`

Если сайт использует:

```html
<video>
  <track src="captions.vtt">
</video>
```

универсального extractor достаточно.

# 5. Полнота захвата

| Метод | Всё видео сразу | Только часть | Live |
|---|---:|---:|---:|
| `.vtt` / `.ttml` / `.srt` файл | ✅ | — | Обычно нет |
| `TextTrack.cues` | ✅ обычно | ✅ до загрузки | ✅ частично |
| `activeCues` | ❌ | ✅ текущие | ✅ |
| HLS VOD | ✅ | ✅ во время загрузки | — |
| HLS live | ❌ | ✅ окно сегментов | ✅ |
| DASH VOD | ✅ | ✅ | — |
| DASH live | ❌ | ✅ окно | ✅ |
| CEA | ✅ если декодировать весь VOD | ✅ | ✅ |
| private API | Зависит | Зависит | Зависит |
| DOM | ❌ | ✅ текущий текст | ✅ |

Главные причины неполного захвата:

- lazy loading;
- `track.mode = disabled`;
- сегментированные HLS/DASH;
- live sliding window;
- текущие `activeCues`;
- captions, появляющиеся только во время playback.

# 6. Рекомендуемая архитектура

```text
SubtitleController
        │
        ├─ NativeTextTrackExtractor
        ├─ DirectFileExtractor
        ├─ HLSExtractor
        ├─ DASHExtractor
        ├─ PlayerApiExtractor
        ├─ PlatformAdapters
        ├─ NetworkExtractor
        └─ DOMExtractor
                │
                ↓
          Format parsers
      VTT / TTML / SRT / JSON
                │
                ↓
           Normalizer
                │
                ↓
      SubtitleTrack / Cue[]
                │
                ↓
 translate / search / summary
```

Порядок попыток:

1. `video.textTracks`
2. `<track src>`
3. официальный player API
4. HLS / DASH manifests
5. platform adapter
6. network observation
7. DOM captions

# 7. Chrome Extension

Content script обычно работает в `ISOLATED` world.

Для обычного DOM и `video.textTracks` этого достаточно.

Если нужно обращаться к JS-объектам самого player:

```text
MAIN world
```

может понадобиться отдельный injected script с message passing.

Не стоит выполнять всю extension-логику в `MAIN`.

---

## Network

`chrome.webRequest` хорошо подходит для обнаружения:

```text
.vtt
.m3u8
.mpd
subtitle
caption
timedtext
```

Но он не даёт универсального удобного доступа к response body.

Для глубокого захвата можно использовать:

```text
chrome.debugger
+ Chrome DevTools Protocol
+ Network.getResponseBody
```

Но это тяжёлое разрешение, поэтому лучше делать его опциональным.

# 8. Live

Live-subtitles лучше моделировать как stream событий:

```ts
interface SubtitleEvent {
  trackId: string;
  startMs: number;
  endMs?: number;
  text: string;
  final: boolean;
}
```

Pipeline:

```text
cue / segment / DOM mutation
 → parse
 → deduplicate
 → update/replace
 → save history
```

Для live полный transcript часто можно получить только если расширение само сохраняет captions во время просмотра.

---

# 9. DRM

DRM/EME может полностью закрывать доступ к raw audio/video.

Но subtitle track иногда идёт отдельным незашифрованным VTT/TTML ресурсом.

Поэтому:

```text
DRM video ≠ обязательно недоступные subtitles
```

Но если captions находятся внутри защищённого media pipeline, универсального способа их извлечь нет.

Обход DRM не следует использовать.

---

# 10. Риски

Нужно учитывать:

- нестабильность private API;
- изменение DOM selectors;
- signed URL с коротким сроком жизни;
- cross-origin iframe;
- `host_permissions`;
- SPA navigation;
- lazy loading;
- DRM;
- copyright;
- условия использования платформ;
- ограничение на хранение и распространение transcript.

---

# Итог

Лучшее решение:

```text
унифицировать не способ получения,
а результат получения.
```

То есть все источники приводить к:

```text
SubtitleTrack
 └─ SubtitleCue[]
      ├─ start
      ├─ end
      └─ text
```

Универсально хорошо покрываются:

- `<track>`;
- WebVTT;
- `TextTrack`;
- HLS;
- DASH.

Отдельные адаптеры нужны прежде всего для:

- YouTube;
- Netflix;
- Coursera;
- других платформ с private player API.

Vimeo можно интегрировать существенно стабильнее через официальный SDK/API.
